# 血染钟楼工具 产品设计与实现文档 (PRD)

本文档记录了血染钟楼工具的核心功能改进、UI 设计逻辑以及技术实现细节。

## 1. 视觉风格与 UI 规范

### 1.1 哥特式暗黑幻想风格
为了契合《血染钟楼》的游戏氛围，全站采用了统一的哥特式暗黑幻想风格。
- **背景**: 深色半透明背景，配合毛玻璃效果（Backdrop Blur）。
- **色彩**: 
  - 强调色：深红/金边。
  - 文本：复古羊皮纸色（`#e2d1b0`）或纯白。
- **边框**: 具有金属质感的金色边框，圆角设计，带有微妙的阴影（Box Shadow）。
- **字体**: 优先使用带有古典韵味的衬线字体。

### 1.2 弹窗统一化 (Unified Modals)
所有弹窗（角色选择、状态选择、设置等）遵循相同的样式规范，确保用户体验的一致性。
- **实现逻辑**: 通过封装 `Modal` 组件，提供可配置的 `width` 和 `title` 属性，内部采用 CSS 变量和统一的类名管理样式。

## 2. 座位组件 (Seat Component) 逻辑

### 2.1 层级结构 (Hierarchy)
为了保证交互的直观性，座位的组件层级按照以下优先级排列（从高到低）：
1. **交互层**: 状态管理按钮 (AddStatusButton)、状态图标 (Status Tokens)、投票标记 (Vote Marker)。
2. **信息层**: 玩家信息面板（姓名、座位号）。
3. **基础层**: 角色令牌 (Role Token)。

### 2.2 动态层级与悬停逻辑 (Hover Logic)
- **需求**: 当鼠标悬停在角色令牌或其相关的状态组件上时，该座位的整体层级应提升至页面最高。
- **技术实现**: 
  - 在 `RoundTable` 中维护 `hoveredIndex` 状态。
  - 通过 `pointer-events: none` 禁用容器的干扰，仅在 `RoleToken` 及其子组件区域启用 `pointer-events: auto`。
  - 精细化管理 `onMouseEnter` 和 `onMouseLeave` 监听器，确保在角色令牌与状态按钮之间移动时，层级保持最高且不被意外取消。
  - 修复了悬停范围重叠问题，确保点击精确度。

### 2.3 状态管理按钮 (AddStatusButton)
- **位置**: 位于角色令牌的左上角。
- **样式**: 
  - 尺寸为状态图标的 0.8 倍，保持平衡。
  - 哥特式圆形按钮，内含深红色加号（+）。
  - 具有悬停缩放效果。

## 3. 布局与自适应 (Layout)

### 3.1 座位尺寸优化
根据座位总数动态调整令牌大小，确保 10-15 人局时视觉效果一致：
- **<= 9 人**: 50px (放大 33%)
- **10-15 人**: 42.5px (放大 13%)
- **> 15 人**: 37.5px (基准大小)

## 4. 关键问题修复 (Bug Fixes)

- **角色选择失败**: 修复了因父容器 `pointer-events` 设置不当导致的点击拦截问题。
- **重复 Key 警告**: 在 `RoundTable` 的动态渲染中，结合 `index` 和 `seat.id` 生成唯一 Key，解决了 React 控制台警告。
- **控制台错误清理**: 清理了 `script.js` 中的语法错误及 `Token.tsx` 等组件中未使用的变量/导入，提升了代码健壮性。
- **剧本切换清理**: 修复了更换剧本后，圆桌上的角色信息（状态、角色）未被彻底清空的问题。现在通过 `RESET_SEATS` 动作保留座位数和玩家名，但重置其余所有状态。

## 5. 交互改进

- **角色选择弹窗标题**: 动态显示为“为 xx 号玩家选择角色”，提升了操作的明确性。
- **移除冗余组件**: 删除了不再使用的 `MoreButton` 组件，简化了代码库。

## 6. 行动顺序系统 (Action Order)

### 6.1 逻辑设计
- **计算机制**: 根据当前游戏阶段（首夜/非首夜），自动提取在场角色的行动顺序值。
- **相对排序**: 系统会自动过滤掉无行动的角色，并将原始值转换为从 1 开始的相对序号，使玩家一目了然今晚的行动顺序。

### 6.2 技术实现
- **数据流**: `RoundTable` 组件负责计算顺序映射表，并通过 `actionOrder` 属性下发给 `Seat`。
- **视觉展示**: 
  - 在 `RoleToken` 的左侧显示一个带有金色渐变和黑色边框的圆形数字标记。
  - **避开滤镜**: 标记被放置在 `RoleToken` 滤镜容器之外，确保在角色死亡（变暗）时，行动序号依然保持高亮清晰。
  - **SVG 溢出处理**: 针对 `Seat.tsx` 中的 `foreignObject` 设置 `overflow: visible`，防止序号在 Token 边缘被裁剪。

## 7. 玩家状态管理逻辑

### 7.1 生死状态 (Life/Death)
- **死亡样式**: 死亡不再是简单的透明或黑色，而是一套复合的视觉效果：
  - **径向渐变**: 中心透明，边缘深红黑色的蒙版。
  - **纹理叠加**: 模拟划痕、陈旧感的叠加层，增加层次感。
  - **动态装饰**: 中心显示带有 `deathPulse` 呼吸动画的红色骷髅图标，并带有强烈的阴影滤镜。
- **逻辑**: 初始为存活，点击状态弹窗中的切换按钮可改变生死，改变角色时自动重置为存活。

### 7.2 阵营管理 (Faction/Flip)
- **初始绑定**: 阵营初始由角色类型决定（镇民/外来者为善良，爪牙/恶魔为邪恶）。
- **手动反转**: 支持通过“反转”按钮手动切换阵营（如“邪恶的镇民”）。
- **局部倒置**: 阵营反转时，仅倒置角色图片（Image），下方的角色名称（Name）保持正向，确保可读性。
- **技术实现**: 在 `Token.tsx` 中引入 `imageRotation` 属性，通过 CSS `transform: rotate()` 实现局部翻转。

## 8. 投票标记系统 (Vote Marker System)

### 8.1 核心逻辑
- **默认状态**: 所有存活玩家默认拥有投票标记 (`hasVote: true`)。
- **展示条件**: 仅当玩家处于**死亡状态** (`isDead: true`) 时，投票标记才会显示在界面上。
- **交互逻辑**: 
  - 点击投票标记可切换其状态（消耗/恢复）。
  - **消耗**: 图标变为灰色，透明度降低。
  - **恢复**: 图标变为蓝色，高亮显示。
- **数据同步**: 顶部的游戏信息栏会自动统计全场剩余的有效票数 (`gameStats.voted`)。

### 8.2 UI 实现
- **位置**: 位于玩家信息组件 (`SeatInfo`) 的右上角，底部与信息组件顶部对齐，右侧对齐。
- **样式**: 使用 FontAwesome `fa-vote-yea` 图标，无边框设计，通过颜色变化（蓝/灰）表达状态，与顶部信息栏图标保持一致。
- **层级处理**: 作为一个独立的 `foreignObject` 放置在 `Seat.tsx` 的顶层，确保不被其他组件遮挡，且不影响悬停逻辑。

## 9. 移动端支持策略

为了保证最佳的说书人体验（复杂的拖拽、悬停、信息展示），本工具目前**仅支持 PC 端访问**。
- **检测机制**: 通过 `navigator.userAgent` 或屏幕宽度检测移动设备。
- **用户反馈**: 移动端访问时会展示全屏提示 "暂不支持移动端，请复制链接前往PC端使用"，并阻断其他操作。

## 10. 版本管理与部署

### 10.1 自动化工作流
项目内置了基于 Git 的版本管理脚本 (`scripts/git-manager.sh`)，封装了常用的 Git 操作。
- **`npm run save`**: 提交并推送代码到 GitHub `main` 分支。
- **`npm run release`**: 创建带时间戳或自定义版本的 Git Tag，并推送到远程。
- **`npm run versions`**: 列出所有已发布的版本。
- **`npm run undo/reset`**: 提供安全和强制的回滚选项。

### 10.2 部署架构
- **平台**: Vercel (前端托管) + GitHub (代码仓库)。
- **触发机制**: 
  - Push to `main` -> 触发 Vercel 预览/生产部署。
  - Push Tag -> 触发 Vercel 独立版本部署 (不会被后续 commit 覆盖)。
